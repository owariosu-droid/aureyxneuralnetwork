# Connect Nox Community

The frontend is prepared; a real Supabase project is not connected or tested yet. Offline encrypted spaces work independently of Supabase. The community only hosts audio a member explicitly publishes. It is not a private cloud-backup service.

1. Create a Supabase project and run `community.sql` once in its SQL editor. It creates publication/report tables, ownership RLS policies, and the deliberately PUBLIC `community-audio` bucket with a 50 MB file limit and audio MIME restrictions. Inspect existing policies if using a shared project; broad older policies can override restrictions. Do not add an allow-all storage policy.
2. Enable email OTP/magic-link authentication. Set the production Site URL to `https://aureyxneuralnetwork.vercel.app` and allow `https://aureyxneuralnetwork.vercel.app/community` as a redirect. Add your exact local test origin separately. Configure email delivery and authentication rate limits in Supabase.
3. In Vercel environment settings, add `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` using the project's PUBLIC publishable key (or legacy anon key). NEVER expose service-role, secret, or database credentials. Redeploy: Vite embeds these public settings at build time. For local development, use `.env.local` based on `.env.example`; the file is ignored.
4. Validate with two separate test accounts. Account A should publish its own selected audio and remove its own post; B can listen to the PUBLIC copy but cannot publish as A or delete A’s post/audio. Signing out locks the local space and clears the composer. Separate tabs do not automatically inherit account tokens. Full refresh requires signing in again because tokens are held in memory.
5. In a dedicated test project, put short-lived user access tokens `NOX_TEST_A_TOKEN` and `NOX_TEST_B_TOKEN` in a local ignored env file alongside the public project settings. Run `node --env-file=.env.local supabase/test-access.mjs`. This performs temporary uploads/posts and cleans up its test objects. It has NOT been run against a real project in this session.

## Before opening signups broadly

This is a prepared integration, not an audited or production-operated community. Enable provider abuse/rate limits and agree moderation, content rules, rights complaints, retention and deletion support. Reports are private to operators in the Supabase dashboard; someone must monitor them. The current 50 MB per-file restriction is enforced at bucket level, not a per-account storage quota. Add server-controlled upload reservations and per-account quotas before selling plans or offering unrestricted public signups. Monitor and clean orphaned uploads, including uploads whose post insert failed, interrupted clients, and files left by deleted accounts. Public files are intentionally downloadable and cannot be recalled from listeners’ devices. Removal does not guarantee immediate purge from every cache.

The client checks the local fingerprint before upload; published fingerprint metadata is self-declared, not proof of authorship. Community players have native controls and a Nox visualizer option. A release consists of public audio, title, artist credits, genre, description and the account's public owner ID; account email is not part of the public feed. No private vault records or notes are automatically copied to Supabase.
